# GD32与CBU5000V210程序逻辑设计说明

## 1. 设计目标

GD32E230K8U6在UWB初始化完成后发送雷达配置命令，并把从UWB串口收到的所有数据原样输出到M_LOG测试点。

支持两种UWB工作模式：

- `sensing_mode = 0`：连续感知。
- `sensing_mode = 1`：基于帧的感知。

工作模式和命令参数均通过宏配置，不需要修改业务代码。

## 2. 串口及DMA资源分配

### 2.1 UWB通信串口

- GD外设：USART1。
- GD引脚：PA2/USART1_TX、PA3/USART1_RX。
- UWB引脚：GPIO01/UART0_RX、GPIO00/UART0_TX。
- 参数：115200 baud、8数据位、1停止位、无校验、无流控。
- 接收方式：DMA通道4循环写入2048字节RAM缓冲区。

### 2.2 M_LOG输出串口

- GD外设：USART0，仅开启发送。
- GD引脚：PA9/USART0_TX。
- 参数：115200 baud、8数据位、1停止位、无校验、无流控。
- 发送方式：DMA通道1从RAM缓冲区分块发送。
- 输出内容：从UWB收到的所有字节，顺序和内容保持不变，不添加GD日志前缀。

PA2/PA3使用USART1、PA9使用USART0，因此UWB通信和M_LOG输出是两个独立硬件串口，不会把Log内容回传给UWB。

GD32E230不支持USART1_RX到USART0_TX的外设直连DMA。实际路径为：

```text
UWB -> USART1_RX -> DMA_CH4 -> RAM循环缓冲区
                                  |
                                  v
M_LOG <- USART0_TX <- DMA_CH1 <- RAM数据块
```

CPU负责查询接收DMA写入位置，并把当前可用数据按最多64字节复制到发送块，再启动发送DMA。这样避免了逐字节接收中断，但GD32本身不支持两个USART之间完全不经过CPU和RAM的DMA直通。

## 3. 启动时序

```text
GD上电
  -> 初始化系统时钟和SysTick
  -> 初始化M_LOG USART0及TX DMA
  -> 初始化UWB通信USART1及RX循环DMA
  -> 等待UWB_STARTUP_DELAY_MS（默认200ms）
       -> 等待期间持续把UWB启动信息转发到M_LOG
  -> 生成并发送UWB配置命令
  -> 主循环持续执行UWB到M_LOG的DMA原样转发
```

启动延时宏：

```c
#define UWB_STARTUP_DELAY_MS 200U
```

## 4. UWB命令格式

GD发送以下ASCII命令，结尾必须是回车`\r`（0x0D）：

```text
f,mode_PRF,power_code,scale_bit,gain_idx,CIR_tap_start,CIR_tap_end,
  sensing_mode,sensing_burst_num,sensing_interval_ms,frame_interval_ms,
  num_cir_per_frame,deep_sleep_en,num_rx_mode,preamble_index\r
```

程序运行时使用不依赖`printf`的十进制转换函数生成命令，避免引入较大的格式化库。

## 5. 配置宏说明

所有宏位于`Application/Inc/uwb_app_config.h`。

### 5.1 通信和模式选择

| 宏 | 默认值 | 含义 |
|---|---:|---|
| `UWB_UART_BAUDRATE` | 115200 | GD与UWB通信波特率 |
| `M_LOG_UART_BAUDRATE` | 115200 | PA9的Log输出波特率 |
| `UWB_STARTUP_DELAY_MS` | 200 | GD上电后等待UWB初始化的时间 |
| `UWB_SENSING_MODE_SELECT` | 连续模式 | 选择连续感知或帧感知 |

模式切换示例：

```c
#define UWB_SENSING_MODE_SELECT UWB_SENSING_MODE_CONTINUOUS
```

或者：

```c
#define UWB_SENSING_MODE_SELECT UWB_SENSING_MODE_FRAME
```

### 5.2 公共雷达参数

| 宏 | 默认值 | 含义 |
|---|---:|---|
| `UWB_MODE_PRF` | 0 | PRF模式：0=BPRF、1=HPRF、2=LG4A |
| `UWB_POWER_CODE` | 40 | 发射功率代码 |
| `UWB_SCALE_BIT` | 6 | CIR幅度缩放参数 |
| `UWB_GAIN_INDEX` | 4 | 接收增益索引 |
| `UWB_CIR_TAP_START` | 0 | 导出CIR的第一个Tap，包含该Tap |
| `UWB_CIR_TAP_END` | 50 | 导出CIR的最后一个Tap，包含该Tap，最大240 |
| `UWB_SENSING_BURST_NUM` | 1 | 每组CIR参与平均的Burst数量 |
| `UWB_NUM_RX_MODE` | 2 | 1=1T1R，2=1T2R |
| `UWB_PREAMBLE_INDEX` | 9 | Preamble索引；默认BPRF使用9 |

### 5.3 连续感知参数

| 宏 | 默认值 | 含义 |
|---|---:|---|
| `UWB_CONTINUOUS_SENSING_INTERVAL_MS` | 100 | 连续模式下相邻CIR输出间隔 |

连续模式下，GD只发送一次启动命令，之后UWB按照该间隔主动输出CIR，不需要GD周期查询。

### 5.4 基于帧的感知参数

| 宏 | 默认值 | 含义 |
|---|---:|---|
| `UWB_FRAME_ROW_INTERVAL_MS` | 10 | 一帧内相邻CIR行的采集间隔 |
| `UWB_FRAME_INTERVAL_MS` | 500 | 相邻完整帧的目标周期 |
| `UWB_FRAME_CIR_COUNT` | 8 | 每帧包含的CIR行数 |
| `UWB_FRAME_DEEP_SLEEP_ENABLE` | 0 | 1=每帧结束后允许深度睡眠，0=不睡眠 |

## 6. 原样转发逻辑

USART1接收DMA持续把UWB字节写入循环缓冲区。主循环每次最多取64字节，再启动USART0发送DMA输出到PA9。转发过程不识别CIR帧头，也不修改二进制数据，因此UWB启动文本、命令应答、提示符和CIR二进制数据都会出现在M_LOG中。

上位机需要根据UWB二进制格式自行同步：

```text
[7字节起始标记][4字节序号/帧号][CIR I/Q数据]
```

## 7. 115200波特率限制

UART采用8N1，每字节占10个串行位。115200 baud理论有效载荷约为11520字节/秒。

单组CIR字节数约为：

```text
1T1R：11 + Tap数量 * 4
1T2R：11 + Tap数量 * 8
```

默认Tap范围0到50，共51个Tap；1T2R单组约419字节，单个串口发送约需36.4ms。默认连续模式间隔100ms，可提供帧间空闲时间。

因为UWB输入和M_LOG输出都为115200，Log出口没有额外带宽余量。参数调整时应注意：

- 不要把连续模式间隔设得小于单组CIR的串口发送时间。
- 增大Tap数量、每帧CIR数量或启用1T2R都会增加数据量。
- DMA减少CPU占用，但不会提高串口本身的带宽。
- 如果后续需要更高采样率，应提高M_LOG波特率或降低CIR数据量。

## 8. 相关源文件

- `Application/Inc/uwb_app_config.h`：用户可修改参数。
- `Application/Src/main.c`：启动延时、发送配置和原样转发主流程。
- `Drivers/UWB/Src/uwb_control.c`：UWB命令生成。
- `Drivers/UWB/Src/uwb_uart.c`：USART1及DMA通道4循环接收。
- `Drivers/Log/Src/m_log.c`：PA9/USART0_TX及DMA通道1发送。
- `BSP/Src/board.c`：SysTick、延时和UWB INT输入。
